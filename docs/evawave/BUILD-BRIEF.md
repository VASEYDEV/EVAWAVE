## 0. Objective

Build EVAWAVE: a VASEY/AI mobile-first PWA that composes, lints, versions and compiles structured musical intent (MusicSpec IR) into the exact input fields of Suno v6, ElevenLabs Music v2 and Google Flow Music, exported as plain files. It does not generate audio. Output serves VASEY.AUDIO; the two brands never conflate.

Phase D is the oracle: Jinn on the Dune v1.2 must be reproducible through the app, and the v1.1 blueprint must fail the meter linter for the reasons it failed in production.

## 1. Repo decision rule (Session 0 executes it)

A1 stands: one codebase, EVAWAVE is the product, `musicspec` is a pure core inside it. Which git repository that is depends on what the compiler repo actually contains, which only the agent can see:

- If the compiler repo has runnable TypeScript serializers (`compileSuno`, `compileEleven`, `resolveLineage`) with a passing test suite → work on branch `feat/evawave` in that repo; retrofit starter kit v3.0 and CLAUDE.md v3.0.0 there.

Either way the compiler's IR v0.2 is the spine and the docs in this handoff are the spec. The agent reports which branch of the rule fired and why before writing code.

## 4. Test plan

- Unit: every pure function in `src/core` (vitest). Serializers are snapshot-tested against the oracle payloads with the snapshot marked informational; the assertions are clause coverage, budgets and lint parity, not byte equality.
- Property: `barmath` — for random specs, `runtimeSec` equals the sum of section durations plus pickups and silence; `music_length_ms` equals the sum of Eleven chunk durations.
- Negative fixtures: v1.1 blueprint (meter failure), a spec with an artist name in `leadNote` (LN-1), a contrast phrase without return rule (CP-1), a 9-instrument section (SC-1 block).
- Integration: Supabase RLS with two test users; intake routes with a mocked LLM returning a fixed patch.
- E2E (Playwright, mobile viewport): S6 and S10 flows.
- Never in tests: real audio uploads, real artist names, real lyrics.

## 5. Non-goals for v1

Audio generation; API dispatch to engines; voice-memo ASR and image-to-mood (v1.1); Udio serializer; user-generated taxonomy; lyric writing; uploading reference audio anywhere.
